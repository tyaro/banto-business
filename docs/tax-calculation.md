第2章のチェックボックスは Phase 5（請求）での実装確認用。仕様上の未決事項は残っていない。

## 1. 前提

| 項目 | 値 |
|---|---|
| 事業者区分 | **適格請求書発行事業者**（2026-08-20 決定） |
| 登録番号 | **設定データ（settings）として保持する。実値はリポジトリに書かない**（`CLAUDE.md` 第8章）。Invoice 確定時に Invoice へスナップショット |
| アプリ内の金額基準 | **税抜**（2026-08-20 決定。案件採算の売上・原価・粗利は全て税抜。消費税は預り金として採算に含めない） |

| 課税方式 | **アプリでは保持しない**（原則課税 / 簡易課税のいずれでも採算計算は税抜のまま。申告は会計ソフト側の責務） |

## 2. 適格請求書の必須記載事項

請求書PDFに以下を必ず出力する。

- [ ] 適格請求書発行事業者の氏名または名称
- [ ] 登録番号（T + 13桁）
- [ ] 取引年月日
- [ ] 取引内容（軽減税率対象品目である旨を含む）
- [ ] 税率ごとに区分して合計した対価の額
- [ ] 税率ごとの消費税額
- [ ] 税率ごとの適用税率
- [ ] 交付を受ける事業者の氏名または名称

### レイアウト上の注意

- 軽減税率対象がある場合、対象品目に記号（※等）を付し、記号の意味を欄外に注記する
- 税率区分が1種類のみの場合も、税率と税額を明示する

## 3. 税率区分

| コード | 税率 | 用途 |
|---|---|---|
| `STANDARD_10` | 10% | 標準税率。開発費・設計費・交通費・宿泊費・部材費等 |
| `REDUCED_8` | 8% | 軽減税率。飲食料品等 |
| `EXEMPT` | — | 非課税 |
| `OUT_OF_SCOPE` | — | 不課税 |

### 経費分類ごとの既定税区分

| 経費分類 | 既定 | 備考 |
|---|---|---|
| 交通費 | `STANDARD_10` | 国内。国際線は免税のため要個別判断 |
| 宿泊費 | `STANDARD_10` | 宿泊税・入湯税は不課税のため分離が必要か Phase 1 で判断 |
| 送料 | `STANDARD_10` | |
| 部材費 | `STANDARD_10` | |
| 消耗品 | `STANDARD_10` | |
| 外注費 | `STANDARD_10` | |
| その他 | `STANDARD_10` | 既定。非課税・不課税に当たるものは行ごとに変更する |

**既定値であり、行ごとに変更可能とする。**

### 請求側（InvoiceLine）の税区分

**立替経費を顧客へ請求する行の税区分は一律 `STANDARD_10`**（2026-08-20 決定）。自分が一度支払い、役務の対価に含めて再請求する形をとるため、仕入側 Expense の税区分（国際線の不課税など）は請求側へ引き継がない。行ごとの変更は可能とする（軽減税率の立替が発生した場合に備える）。

仕入側の税区分は Expense に保持したままとし、仕入税額控除の集計に使う。

## 4. 端数処理

### 4.1 原則

**端数処理は1つの適格請求書につき、税率ごとに1回。**

明細行ごとの個別端数処理は行わない。

### 4.2 計算順序

```
1. 明細行を税率区分ごとにグループ化
2. 各グループ内で対価の額を合計          ← ここまで端数処理なし
3. グループごとに 合計額 × 税率 を計算
4. グループごとに1回だけ端数処理          ← 端数処理はここのみ
5. 各グループの税額を合算して請求書合計税額とする
```

### 4.3 端数処理方向

| 項目 | 値 |
|---|---|
| 消費税額の端数処理 | **切捨て（既定値。2026-08-20 決定）** |
| 処理桁 | 1円未満 |
| 設定での変更 | 四捨五入 / 切上げも選択可能にする |
| マイナス金額の向き | **ゼロ方向**（絶対値を処理して符号を戻す。2026-08-20 決定） |

**マイナス（値引き行を含み税率区分の合計が負になる場合）の定義：** `-3,333.5` は切捨てで **`-3,333`**（ゼロ方向）とする。負の無限大方向の `-3,334` ではない。実装は絶対値に対して端数処理を行い符号を戻す（Rust の `i64` 除算はゼロ方向に丸まるため、整数演算がそのままこの定義になる）。

- 設定値として保持し、Invoice に処理方向をスナップショットする
- 一度発行した請求書の端数処理方向は、設定変更後も遡って変わらないこと

### 4.4 明細行単価の端数

明細行の `数量 × 単価` で端数が出る場合の扱い：

**決定（2026-08-20）：単価は整数円のみ許容する。**

- 単価に小数を持たせない（`CLAUDE.md` 1.1 の浮動小数点禁止と整合）
- 工数を請求する行は「時間単価 × 時間」で行金額が決まるが、**時間側で端数が出るため、行金額を整数で確定させてから明細に載せる**。行金額の算出は切捨て（1円未満）とし、内部原価の計算（`floor(分 × 単価 ÷ 60)`）と同じ丸め方を使う
- 行金額が確定した後は、税額計算は税率区分ごとに1回だけ端数処理する（4.1 の原則は変わらない）

## 5. 実装インターフェース（案）

```rust
// src-tauri/src/domain/tax.rs

pub enum TaxCategory {
    Standard10,
    Reduced8,
    Exempt,
    OutOfScope,
}

pub enum RoundingMode {
    Floor,
    Round,
    Ceil,
}

pub struct TaxLine {
    pub amount: i64,          // 円。税抜
    pub category: TaxCategory,
}

pub struct TaxGroupResult {
    pub category: TaxCategory,
    pub rate_bp: u32,         // basis point (10% = 1000)
    pub taxable_amount: i64,  // 税率区分ごとの対価合計
    pub tax_amount: i64,      // 端数処理後の税額
}

pub struct TaxSummary {
    pub groups: Vec<TaxGroupResult>,
    pub total_taxable: i64,
    pub total_tax: i64,
    pub total_amount: i64,    // 税込合計
}

pub fn calculate_tax(
    lines: &[TaxLine],
    rounding: RoundingMode,
) -> TaxSummary;
```

**この関数は純粋関数とし、DB・Tauri に依存させない。**

## 6. テストケース表

実装時に以下を全てテストする。金額は全て**税抜**、既定の端数処理は**切捨て**（1円未満）。

| # | ケース | 入力 | 期待値 |
|---|---|---|---|
| T-01 | 10%のみ・端数なし | 100,000円 × 10% | 税額 10,000 / 税込 110,000 |
| T-02 | 10%のみ・端数あり（既定の切捨て） | 33,333円 × 10% | 3,333.3 → **税額 3,333** / 税込 36,666 |
| T-03 | 端数処理方向の切替（同一入力で差が出ること） | 33,335円 × 10%（= 3,333.5） | 切捨て **3,333** / 四捨五入 **3,334** / 切上げ **3,334** |
| T-04 | 8%のみ | 33,333円 × 8% | 2,666.64 → **税額 2,666** / 税込 35,999 |
| T-05 | 10% + 8% 混在 | 10%: 33,333円 / 8%: 33,333円 | 税額 3,333 + 2,666 = **5,999** / 対価合計 66,666 / 税込 72,665 |
| T-06 | 10% + 不課税 混在 | 10%: 10,000円 / 不課税: 5,000円 | 税額 **1,000**（不課税分は税額計算の対象外）/ 対価合計 15,000 / 税込 16,000 |
| T-07 | 全税率混在 | 10%: 10,000 / 8%: 10,000 / 非課税: 5,000 / 不課税: 5,000 | 税額 1,000 + 800 = **1,800** / 対価合計 30,000 / 税込 31,800。**非課税と不課税は別グループとして区別して出力する** |
| T-08 | **明細行ごとに端数処理した場合と結果が異なることの検証** | **33,335円 × 3行（10%）** | 行ごと処理: floor(3,333.5) × 3 = **9,999** / 区分ごと処理: floor(100,005 × 10%) = **10,000**。**差 1 円が出ること**が本ケースの合格条件 |
| T-09 | 明細0件 | `[]` | 全て 0（グループも空） |
| T-10 | 金額0円の明細を含む | 10%: 10,000円 + 10%: 0円 | 税額 1,000。**0円行だけの税率区分をグループとして出力するか**は下記の未決事項 |
| T-11a | 値引き行あり・区分合計はプラス | 10%: 100,000円 + 値引き −33,335円（合計 66,665円） | 6,666.5 → **税額 6,666**（ゼロ方向切捨て） |
| T-11b | 値引き行あり・**区分合計がマイナス** | 10%: −33,335円 | −3,333.5 → **税額 −3,333**（ゼロ方向）。負方向切捨ての −3,334 になっていたら不合格 |
| T-12 | 端数処理方向のスナップショット | 設定を切捨て→四捨五入に変更 | 既発行 Invoice の税額は不変 |

> **T-08 の入力値を修正した（2026-08-20）。** 元の `33,333円 × 3行` では、行ごと処理も区分ごと処理も 9,999 円で一致してしまい（floor(3,333.3) × 3 = 9,999、floor(99,999 × 10%) = 9,999）、**端数処理の位置を誤った実装を検出できない**。`33,335円 × 3行` にすると 9,999 と 10,000 に分かれ、本来の目的（リグレッション検出の基準ケース）を果たす。

### T-10 に関する決定

金額 0 円の明細しか無い税率区分を、`TaxSummary.groups` に「対価 0・税額 0」のグループとして出力するか、グループごと省略するか。請求書PDFの税率区分ごとの記載にそのまま出るため、表示要件とあわせて決める。

- **決定（2026-08-20）：出力しない。** 対価合計が 0 の税率区分はグループを作らない（請求書に「10% 対象 0円」の行を出さない）。0円の明細行そのものは明細として残してよい

**T-08 は特に重要。** 端数処理の位置を誤った実装をリグレッションで検出するための基準ケースとする。
