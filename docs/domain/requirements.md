# 要件定義

Banto Business が満たすべき要件。`docs/plan.md` 第16章の MVP を、Phase 1 の決定内容で具体化したもの。

---

## 1. 目的と範囲

個人事業の案件管理を一元化し、**案件ごとの採算を根拠のある数値で把握できる**ようにする。

| 範囲内                  | 範囲外                                                     |
| ----------------------- | ---------------------------------------------------------- |
| 顧客・案件の管理        | 複式簿記・仕訳・決算・確定申告                             |
| 工数・出張・経費の記録  | 給与計算                                                   |
| 案件採算の算出          | 電子帳簿保存法の要件を満たす証憑保管（正本は会計ソフト側） |
| 適格請求書の発行（PDF） | 見積書の作成（MVP対象外）                                  |
| 入金消込・未入金管理    | 多通貨・海外取引                                           |

## 2. 機能要件

### 2.1 マスタ（Phase 2）

| ID   | 要件                                                                                       |
| ---- | ------------------------------------------------------------------------------------------ |
| F-M1 | 顧客を登録・編集・一覧できる。顧客コードは重複を許さない                                   |
| F-M2 | 顧客に締日・支払条件（`closing_day` / `payment_month_offset` / `payment_day`）を保持できる |
| F-M3 | 案件を登録・編集・一覧でき、顧客に紐づく。案件番号は `YYYY-NNN` で自動採番し、手修正できる |
| F-M4 | 案件の状態を `見込 / 受注 / 進行中 / 検収待ち / 完了 / 失注 / 保留` から選べる             |
| F-M5 | 作業分類ごとの内部原価レートを設定できる                                                   |

### 2.2 工数・経費（Phase 3）

| ID   | 要件                                                                                                         |
| ---- | ------------------------------------------------------------------------------------------------------------ |
| F-W1 | 案件・日付・作業分類・時間（分）・作業内容で工数を記録できる                                                 |
| F-W2 | 工数の記録時に、作業分類の内部原価レートを既定値として提示し、**行に焼き付ける**。行ごとの手動上書きができる |
| F-W3 | 内部原価は `floor(分 × 適用単価 ÷ 60)` で行ごとに確定し、保存する                                            |
| F-E1 | 案件・日付・分類・支払先・金額・税区分で経費を記録できる                                                     |
| F-E2 | 経費に「顧客請求対象（`billable`）」と「請求済（`invoiced`）」を**別々に**保持できる                         |
| F-E3 | 経費に領収書を添付できる（Banto の Attachments を使う）                                                      |
| F-T1 | 出張を登録すると、移動工数（往復2件）・現地作業工数（日数分）・交通費・宿泊費を**一括生成**できる            |
| F-T2 | 生成物は通常の WorkLog / Expense であり、生成後に個別編集・削除できる                                        |
| F-T3 | 出張を削除しても生成物は消えず、`trip_id` が NULL 化される。削除時に影響件数を表示する                       |

### 2.3 採算（Phase 4）

| ID   | 要件                                                                                               |
| ---- | -------------------------------------------------------------------------------------------------- |
| F-P1 | 案件詳細で、契約額 / 案件売上 / 工数原価 / 直接経費 / 粗利 / 粗利率 を確認できる                   |
| F-P2 | **実質時間単価を「移動込み」「移動除く」の2種で必ず併記する**。片方だけを返す API を作らない       |
| F-P3 | 「移動」の判定は作業分類のフラグ（`excluded_from_effective_rate`）で行い、コード文字列を比較しない |
| F-P4 | 案件売上は**確定済 InvoiceLine の税抜合計**とする。未請求の作業・経費は売上に立たない              |
| F-P5 | 進行中案件で粗利がマイナスに見える誤読を防ぐため、**請求進捗（案件売上 ÷ 契約額）を併記する**      |
| F-P6 | 顧客請求対象の経費は原価にも売上にも計上する（両建て）                                             |
| F-P7 | 採算値は保持せず、常に WorkLog / Expense / InvoiceLine から導出する                                |
| F-P8 | 経費は**行ごとに仕入側の税区分で税抜へ換算**して原価に計上する（1円未満切捨て、決定 C-16）         |

### 2.4 請求（Phase 5）

| ID    | 要件                                                                                                   |
| ----- | ------------------------------------------------------------------------------------------------------ |
| F-I1  | 顧客・期間を指定し、未請求の工数・経費から請求明細の候補を作成できる                                   |
| F-I2  | 1つの請求書に**複数案件の明細**を含められる。1つの案件に**複数の請求書**を発行できる                   |
| F-I3  | 明細の税区分は行ごとに設定できる。立替経費の再請求は既定で `STANDARD_10`                               |
| F-I4  | 値引き行（マイナス金額）を入力できる                                                                   |
| F-I5  | 消費税は**税率区分ごとに1回だけ端数処理**する。明細行ごとの端数処理は行わない                          |
| F-I6  | 端数処理方向は設定値（既定：切捨て）。マイナスの場合は**ゼロ方向**に処理する                           |
| F-I7  | 確定時に、請求書番号の採番・明細・税集計・端数処理方向・発行者情報・支払期限を**スナップショット**する |
| F-I8  | 確定後は明細を編集できない。訂正は取消（赤伝）＋新規発行で行い、`corrected_invoice_id` で対応付ける    |
| F-I9  | **適格請求書の記載要件を満たす PDF** を生成できる（Banto の Report 機能を使う）                        |
| F-I10 | 支払期限は顧客の締日・支払条件から自動計算し、Invoice に保存する（手修正可。土日祝の調整はしない）     |
| F-I11 | 工数を請求する行の単価は**案件マスタの請求時間単価**から取る（決定 C-17）。内部原価レートは使わない    |
| F-I12 | 立替経費の再請求額は**税抜換算額**とする（決定 C-18）。実費請求なら粗利影響がゼロになる                |

### 2.5 入金（Phase 6）

| ID   | 要件                                                                                                              |
| ---- | ----------------------------------------------------------------------------------------------------------------- |
| F-Y1 | 入金を登録し、**複数の請求書へ充当**できる（まとめ入金）                                                          |
| F-Y2 | 1つの請求書に**複数の入金を充当**できる（分割入金）                                                               |
| F-Y3 | 充当時に差額理由コード（振込手数料 / 源泉徴収 / 値引き / 過入金 / その他）を記録できる                            |
| F-Y4 | 請求書の残額は充当額合計から導出する。**0 未満にはしない**                                                        |
| F-Y5 | 入金状態（一部入金 / 入金済）は保持せず導出する                                                                   |
| F-Y6 | **期限超過（Overdue）は状態として保持せず**、`支払期限 < 今日 AND 残額 > 0 AND 状態 ≠ 取消` で都度評価する        |
| F-Y7 | 未入金・期限超過の一覧をダッシュボードに表示する                                                                  |
| F-Y8 | 差額（手数料・源泉・値引き・過入金）は**残額の計算に含める**（決定 C-19）。理由コードは必須、`OTHER` は備考も必須 |

### 2.6 カレンダー（Phase 7 準備）

Phase 1〜6 の要件定義には無かったが、Phase 7（実運用評価）の準備として追加した。既存データを別の見せ方にするだけで、新しいテーブルも状態も持たない。

| ID   | 要件                                                                                                                          |
| ---- | ----------------------------------------------------------------------------------------------------------------------------- |
| F-C1 | 月グリッドに、日別の工数（合計時間と案件別の内訳）・経費・出張・請求の締日／支払期限・入金を表示する                          |
| F-C2 | **工数の入力が無い過去の平日**を強調する（`docs/plan.md` Phase 7 の評価項目「工数入力継続性」の観測手段）。土日と未来は対象外 |
| F-C3 | 祝日は扱わない（祝日表は毎年変わるため保持しない）                                                                            |
| F-C4 | 升目から、その日付を初期値にして工数を追加できる                                                                              |
| F-C5 | 集計値は保持せず、毎回 `work_logs` / `expenses` / `trips` / `invoices` / `payments` から導出する                              |
| F-C6 | 期限超過（F-Y6）の判定はカレンダーでは行わない。「その日が支払期限」以上の意味を升目に持ち込まない                            |

**経費は税込の実支出をそのまま表示する。** 税抜換算（決定 C-16）は採算（F-P1〜）の計算であり、カレンダーは金額の出どころを指す画面なので換算しない。同じ数字を2箇所で丸めると食い違う。

## 3. 非機能要件

| ID  | 要件                                                                                                     |
| --- | -------------------------------------------------------------------------------------------------------- |
| N-1 | ローカルファースト。ネットワーク接続なしで全機能が動く（SQLite）                                         |
| N-2 | 日次バッチを前提にしない。**アプリを起動しない日があっても状態が実態とずれない**                         |
| N-3 | 金額は全て整数（円）で保持し、浮動小数点を経由しない                                                     |
| N-4 | 過去に確定した数値（案件採算・発行済請求書）が、マスタ変更で遡って変わらない                             |
| N-5 | 将来 PostgreSQL へ移行しうるため、SQLite 固有機能への依存を最小化する。マイグレーションは2方言で対にする |
| N-6 | 業務日付は JST のローカル日付（`TEXT`）。UTC 変換で日付がずれる実装をしない                              |
| N-7 | 実データ（業務DB・バックアップ・領収書）と事業者情報の実値をリポジトリに含めない（public リポジトリ）    |

## 5.1 デバイス間同期（Phase 8）

方式は `docs/domain/sync.md`。

| ID   | 要件                                                                                                     |
| ---- | -------------------------------------------------------------------------------------------------------- |
| F-S1 | 外出先ではネットワークに繋がらなくても、端末単独で読み書きが完結する                                     |
| F-S2 | 同期は自宅 LAN 内でのみ行い、インターネットに何も公開しない                                              |
| F-S3 | 顧客・案件・各マスタ・工数・経費・出張を双方向に同期する                                                 |
| F-S4 | 請求・入金は PC 専用とし、同期しない。ただし請求の結果（`invoiced`）は工数・経費の行として届く           |
| F-S5 | id は端末ごとに重ならないレンジで採番し、同じ id が全端末で同じ行を指す                                  |
| F-S6 | 変更追跡は outbox で行い、時計に依存しない                                                               |
| F-S7 | 削除は論理削除とし、削除が同期先へ伝わる                                                                 |
| F-S8 | 衝突は自動解決せず利用者に提示する。ただし「片方が `invoiced` を立てただけ」「全列同値」は自動で解決する |

| ID   | 検証内容                                                                              |
| ---- | ------------------------------------------------------------------------------------- |
| V-7  | 双方向同期：両端末で別の行を追加 → 双方に揃う                                         |
| V-8  | 削除の伝播：片方で削除 → もう片方でも消える（未同期の行と区別できる）                 |
| V-9  | 衝突検出：同じ行を両端末で編集 → 自動で片方を捨てず提示する                           |
| V-10 | 自動解決：片方が `invoiced` を 0→1 にしただけの場合は提示せず PC 側を採る             |
| V-11 | id レンジ：2 端末で採番した id が衝突しない。外部キーが同期後も正しい行を指す         |
| V-12 | スナップショット：レートマスタを同期した後も、既存の工数原価が不変（`CLAUDE.md` 1.2） |

## 6. MVP に含めないもの

`docs/plan.md` 第17章に従う。実運用（Phase 7）で必要性が確認されたもののみ追加する。

- 見積書の作成・見積から案件への変換
- 前受金の繰越管理（過入金は理由コードでの記録に留める）
- 定期請求の自動生成
- 複数ユーザーでの同時利用
- 外貨建て請求
