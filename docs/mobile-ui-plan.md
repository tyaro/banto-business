# スマホ母艦の UI 改善計画

作成: 2026-08-24（スマホ母艦決定 `docs/domain/sync.md` 0節 と同日）
状態: **計画。実施順は本文 4 章。個々の項目は着手前に確認を取る。**

---

## 0. なぜ今見直すのか

このアプリの UI は「PC で使い、スマホは補助」という前提で組まれてきた。
2026-08-24 にその前提が逆転した —— **スマホ（Pixel 10 Fold）の DB が正本で、
PC はブラウザとして LAN 経由でスマホに接続する**（`docs/domain/sync.md` 0節）。

主入力デバイスが変わったのだから、動線もスマホ基準で数え直す。
本書は代表的な動線を**タップ数でシミュレーション**し、直す価値のある順に並べる。

### 前提

- 画面幅 900px 以下ではサイドバーはオーバーレイ（ハンバーガー → 項目で 2 タップ）
- ログイン後は必ず `/dashboard` に着地する（`routes/login/+page.svelte`）
- ナビは現在 17 項目（`$lib/navigation.ts`）。admin 以外には 13 項目
- 請求・入金の「PC 専用」制約は母艦化で消えた（DB が 1 つになったため）。
  以降の「PC で行う」は**画面の広さによる推奨**であって制約ではない

### 数え方

タップ数は「画面遷移 + 入力欄のフォーカス/選択 + 確定」を 1 ずつ数える。
文字入力そのもの（キーボードの打鍵）は数えない。厳密さより比較可能性を優先する。

## 1. 動線シミュレーション ①: 初期の登録操作（導入日）

まっさらな端末で、最初の工数 1 件を記録できるまで。

| # | やること | 画面 | 概算タップ | 引っかかり |
| - | --- | --- | --- | --- |
| 1 | APK 導入・初回起動 | — | — | `docs/android-build.md` |
| 2 | 初回セットアップ（admin 作成） | login（setup モード） | 4〜6 | 問題なし |
| 3 | 発行者情報（適格請求書） | issuer | 10+ | **どこにあるか知らないと探す**。ナビ後半の admin 群に埋まっている |
| 4 | 内部原価レートの設定 | cost-rates | 分類×2〜3 | **設定を飛ばすと工数保存時に初めてエラーで知る**（分類の既定レート未設定） |
| 5 | 顧客を登録 | customers/new | 8+ | 問題なし |
| 6 | 案件を登録（請求単価も） | projects/new | 10+ | **請求単価を飛ばすと請求書作成時に金額 0 で気付く**（`invoices/new` の doc 参照） |
| 7 | 最初の工数 | quick | 4〜5 | 問題なし |

### 見えた問題

- **順序をアプリが教えてくれない。** 発行者 → レート → 顧客 → 案件 → 工数という
  依存順は `docs/plan.md` を読まないと分からない。飛ばした場合の症状が
  「後工程での分かりにくいエラー・金額 0」として出る。
- ダッシュボードは導入直後は空（未入金なし）で、**次に何をすべきかを示す
  一等地が空白のまま**。
- ナビにデモ画面（tree）が本番と同格で並んでいる。`docs/template-scope.md` 3章で
  削除可と明記済みの M-review デモの名残。

## 2. 動線シミュレーション ②: 使い込んでからの日常動線

### 2.1 工数を 1 件入れる（1 日に数回、最頻の操作）

現状: 起動 → dashboard 着地 → ハンバーガー(1) → クイック入力(1) →
（案件・分類は前回値）→ 分プリセット(1) → 記録(1) = **4 タップ + 遷移待ち**。

- クイック入力自体は既に速い（前回値の記憶・プリセット・画面に留まる設計）。
- 一番高くつくのは**そこへ着くまで**。最頻画面が起動のたびに 2 タップ先にある。

### 2.2 経費を 1 件入れる（レシートをもらった直後）

現状: ハンバーガー(1) → 経費(1) → 新規(1) → 7 項目入力（案件・日付・分類・
支払先・金額・税区分・内容）→ 保存 → **一覧に戻る** → 添付したければ
行を開き直して(1) 領収書を撮って添付。

- **保存すると一覧に戻るため、領収書添付が「開き直し」になる。**
  添付パネルは編集画面にしかない（新規は id が無いので当然）。
  レシートをもらった場で「入力 → その場で撮って添付」が 1 本の流れにならない。
- 税区分は分類の既定（`default_tax_category`）があるのに、フォーム上は
  自分で選ぶ欄として出る（サーバ側は分類から引く仕組みを持っている）。

### 2.3 入力の確認・修正

calendar で月を俯瞰 → 升 → その日の工数 → 行を開いて修正。動線は成立している。
スマホでの月グリッドの見やすさは Phase 7 の実機評価に委ねる（推測で直さない）。

### 2.4 月末: 請求書を作る（月 1 回、PC ブラウザ推奨）

invoices/new: 顧客選択 → 期間 → 候補検索 → チェック → 作成 → 明細整理 → 確定 → PDF。
候補の表が広いので**画面の広い PC ブラウザでやるのが自然**。母艦化で
「スマホの正本データを PC の画面で操作する」がそのまま成立するので、
ここに直すものは今は無い。

### 2.5 月末: 入金消込（月 1 回、PC ブラウザ推奨）

PaymentEditor（充当・差額理由）は表形式。請求と同じく PC ブラウザで足りる。

### 2.6 採算・未入金の確認

dashboard の未入金・期限超過パネル（F-Y7）のみ。**指標の追加は Phase 7 で
「毎日何を見たいか」が決まってから**という既定方針（`dashboard/+page.svelte` の
doc）は妥当なので、本計画でも変えない。

## 3. 改善バックログ（優先度順）

P1 = 小さく、毎日効く。P2 = Phase 7 の実測とセットで判断。P3 = 様子見。

### P1-1. 起動時に前回開いていた画面へ戻る — **実施済み（2026-08-24）**

最頻操作（2.1）の固定費 2 タップを消す。ログイン成功時の `goto('/dashboard')` を
「端末ごとに覚えた前回の画面」へ変える（`ui-settings`、クイック入力の
前回値記憶と同じ仕組み）。覚えが無ければ従来どおり dashboard。

実装メモ（`$lib/banto/lastVisited.ts`）: 記憶の粒度はナビ項目のセクション
パス（`/expenses/123` → `/expenses`）。adminOnly のパスは記憶しない ——
ログイン直後はまだロールが分からないので、誰でも着地できるパスだけ覚える。

### P1-2. 経費の新規保存後、一覧ではなく編集画面へ遷移する — **実施済み（2026-08-24）**

2.2 の「開き直し」を消す。保存 → その行の編集画面（添付パネルがある）へ
遷移すれば、レシートをもらった場で入力から撮影・添付まで 1 本になる。
工数・顧客・案件は従来どおり一覧へ戻る（添付が無いので開き直す理由が無い）。

### P1-3. tree デモをナビから外す（画面ごと削除） — **実施済み（2026-08-24）**

`docs/template-scope.md` 3章で削除可と明記済み。本番のナビ 17 項目を 16 に。
`@banto/tree-svelte` パッケージ自体は同梱のまま（Banto 由来コードは触らない）。

### P1-4. ナビをスマホ向けに 3 群へ区分する — **実施済み（2026-08-24）**

17 項目のフラットな縦一列は、頻度の差が 100 倍ある項目（クイック入力と
audit-log）を同格に見せている。見出しで分ける（並び順は現状維持）:

- **毎日**: ダッシュボード / カレンダー / クイック入力
- **記録と請求**: 顧客 / 案件 / 工数 / 出張 / 経費 / 請求書 / 入金
- **マスタと設定**: レート / 発行者 / ユーザー / 監査ログ / 同期 / 設定

Sidebar は app 層（`$lib/components/Sidebar.svelte`）なので Banto 本体に
手を入れずに済む。見出し分の visual baseline 更新が必要。

### P1-5. 分類の選択式化と一覧の名前表示 — **実施済み（#31）**

通常フォームの作業分類・経費分類を（クイック入力と同様に）選択式にし、
一覧の分類列もコードではなく名前で表示する。

### P2-1. 初期セットアップの道しるべ

1 章の「順序を教えてくれない」対策。dashboard の空状態に
「発行者情報 → レート → 顧客 → 案件 → 工数」のチェックリストを出し、
済んだ項目から消す。**何を『済』と判定するかは実装前に確認**
（例: 発行者=登録番号が入っている、レート=有効分類全部か 1 件以上か）。

### P2-2. 経費フォームの税区分を分類の既定で埋める

分類を選んだら `default_tax_category` を初期値に入れる（変更は可）。
**税計算に関わるため、初期値の埋め方（空欄の扱い・上書き時の挙動）は
実装前に確認を取る**（CLAUDE.md 7章: 税は推測禁止）。

### P2-3. クイック入力に経費タブ

2.2 をさらに縮める案（案件・分類・金額だけの最短経路 + P1-2 の添付動線）。
工数クイックの利用実績を Phase 7 で見てから決める。

### P2-4. dashboard の指標追加 / calendar のスマホ表示密度

どちらも Phase 7 の実測（毎日見たいもの・月グリッドの視認性）が決める。
先回りしない。

### P3. その他

- Android の App Shortcuts（長押し → クイック入力へ直行）。P1-1 で足りるなら不要
- 共有インテントからの下書き投入などは、必要になった実例が出るまでやらない
